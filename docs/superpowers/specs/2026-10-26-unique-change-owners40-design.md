## Approaches and decision
The existing ordered array preserves canonical order without ranks but permits duplicate field owners in producer grammar. More generic uniqueness wording or uniqueItems alone does not exclude different-valued duplicate fields. A fixed-order field dictionary would collapse observable authored order/fact-alias behavior and is outside this transport-only task. A rank dictionary restores the global rank collision observed35. A recursively enumerated remaining-field grammar would encode uniqueness and order jointly but grows combinatorially and risks the fixed byte/compiler limits.

Choose an exact field-owner dictionary plus explicit authored order vector for bounded offline implementation. It structurally prevents multiple value owners per field, while retaining a cross-condition: vector references must bijectively match all active owners. This moves the remaining condition; it does not prove improved Google recognition, state complexity, admission or compliance. ## Rank comparison, counterexamples and causal hypothesis
The previous field dictionary already had structural value-owner uniqueness but independently authored numeric ranks. Distinct owners with equal ranks were invalid; valid gaps0/2 versus3/9 represented the same relative order. New owners/order avoids numeric ranks, gaps, numeric range and tie resolution. It replaces those constraints with an exact reference permutation. That constraint remains global: owner-title active and order[] is invalid, order[title,title] is invalid, order[title,location] with location inactive is invalid, active title+location with order[title] is invalid. None can be repaired by traversal, sorting, deduplication, deleting an unused owner or guessing a missing reference.

For two active owners title(valueA,evidenceU0) and location(valueB,evidenceU1), both order[title,location] and [location,title] are valid and reconstruct different canonical ordered patches. Corresponding changeEvidence and fact aliases must follow that authored order; future facts cannot silently retain old IDs after a reorder. Equal owner values with different evidence remain separate field changes, not deduplicated. Explicit permitted CLEAR of title plus REPLACE of location is a valid multi-edit in either authored order. All-empty owners/order[] is not an implicit CLEAR. Query absence remains controlled solely by unchanged operation/query39.

Recorded39's repeated eventDate rows are refused unchanged by the new public version/alphabet boundary. Do not feed them through a trusted encoder to pick one. A separate canonical expected proposal may encode to one eventDate owner plus one reference, but is a counterfactual, not repair or model-improvement evidence. Prior35 duplicate ranks likewise remain frozen; no dropping ranks or replaying historical decoders/campaigns. Offline semantic counterexamples cover valid arbitrary permutations and invalid ownership/order relations rather than translating historical failed payloads into success.

The bounded hypothesis is that making each typed value/evidence appear in one named field owner can reduce repeated full-row generation while a separate short field-reference list preserves intent. It may instead produce duplicate/missing references; no causal or reliability improvement has been established. Numeric rank removal and dictionary uniqueness alone do not prove convergence. The existing field-owned selected value domains and operation-specific query structures are reused exactly, not pooled or replaced with a permissive common value union. The schema adds only existing object/required/additionalProperties/array/items/min-max/primitive-enum constructs; it does not rely on uniqueItems, contains, prefixItems, conditional/not constraints or provider-enforced bijection. Existing compiler acceptance and byte projections are offline evidence only; actual Google acceptance/internal states/constraint enforcement remain unverified until the separately authorized ONE Formal.
