# Generation-time field capability amendment

Owner authorizes a narrow upstream semantic field allowlist, not model value inference or output repair. Existing canonical/evidence/scoring authorities remain unchanged.

## Design

Derive numeric field capability using the existing field/value ownership predicates against immutable USER sources and accepted canonical context. Distance evidence may allow leadOffsetDays, but never recurrence/count; repeated notification evidence may allow recurrence/count, but never offset. Preserve eligible retained operands and explicit corrections/removal. Capability is only an upper bound on proposal fields, not proof of a value or permission to mutate.

Select a request-specific ProviderWire schema before token measurement and dispatch. Remove disallowed field branches from changes (including their CLEAR carriers); do not alter model output afterward. The wire decoder and all downstream validators remain authoritative even if a provider ignores the constrained schema. Missing-field uncertainties remain expressible; uncertainty alternatives must not bypass the same numeric ownership checks.

All nonnumeric fields retain their existing authority/evidence requirements; this amendment adds no new semantic parser for title/location/date/clock. Unrecognized numeric wording must not silently default to an inferred value. Explicit unsupported recurrence still reaches existing unsupported handling. Preserve CURRENT context versus NEW separation.

## Clarified field upper-bound scope

The root changes schema covers both CURRENT and NEW. Existing event-relation and lead-offset predicates may conservatively open a lead field for an independently grounded instruction while CURRENT retains a series. The downstream validator still checks the model-selected target and value; the allowlist cannot alone eliminate every contextual model error. A bare CURRENT series answer retains the existing count/distance restriction, and count-only language never supplies a lead capability.

Occupied CONFLICT numeric slots keep their field branches for meaningful CLEAR/correction, without authorizing their values. An already-MISSING or null-valued conflicting slot grants no field capability without independent direct support; this amendment adds no removal-language parser. Uncertainty remains available when wording is unsupported or a field is absent.

## Accounting and evidence

Keep the unchanged base wire digest as the reviewed schema-family identity; additionally capture the exact request-specific schema digest and capability digest. Verify the actual outbound schema equals the request's derived schema, not merely a stored label. No hardcoded fresh digest can authorize an unbound dynamic request. Historical static-wire evidence remains historical; never rewrite it.
