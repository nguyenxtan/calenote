# Keyed emission142: explicit daily-cadence presence

Full141 stopped at R07#2/1 because the model wrote the count and event relation
but omitted the independently authored DAILY cadence. No canonical reminder was
created. Engineering141 passed340 files/11036 tests; that is not live acceptance.

The selected keyed schema now has a sufficient presence rule for a complete
positive notification clause: a bounded count of consecutive days before an
event reference, in a sole factual active task asking for a missing reminder
operand. Frequency and count must both be absent from retained state; conflicts
or existing ambiguities decline this bound. The rule is independent of task
title, venue, date, numeric value2, and any fixture identity.

The whole source is checked before the existing cadence/count support predicates
are queried. Only counts2..30 within FINITE_DAILY capabilities qualify. Quoted,
negated, hypothetical, note/title, control-bearing, competing-cadence, distance-only,
single-notification, and unsupported-count sources do not gain a presence rule.
This intentionally covers a sufficient finite source language, not arbitrary
natural language. Retained cadence does not require a redundant write.

The helper returns only a boolean. The selected frequency owner becomes nonempty
and permits SET DAILY; the model still authors that value and its actual evidence.
Missing or contradictory received output is refused unchanged. The encoder does
not insert the missing value. No target, relation, count, dates, clocks, confirmation
or persistence authority is derived by this rule. Canonical contracts, shared
legacy105/106 consumers and business oracles remain unchanged.
